공사 현장의 위험 반경을
실제 거리로 보고, 서로 알린다

SOC-MAP은 공사 현장을 실제 GPS 위치에 등록하고, 굴착기·크레인 같은 장비의 위험 반경을 미터 단위로 계산합니다. 작업자와 장비 운전원의 휴대폰이 서로의 위치를 1초마다 공유해, 위험 구역에 다가가면 본인에게, 들어가면 관리자에게 경보가 갑니다.

배경

장비 사고는 "보이지 않는 반경"에서 일어납니다

고용노동부 집계로 2019~2021년 건설 장비 사망자는 굴착기 63명, 이동식 크레인 33명입니다. 후진하는 굴착기의 사각지대, 회전하는 크레인 붐 아래처럼 위험 범위는 땅 위에 그려져 있지 않습니다.

1위험 범위가 눈에 보이지 않는다작업반경·후방 사각지대·붐 회전 반경은 장비 제원과 방향에 따라 달라지고, 장비가 움직이면 같이 움직입니다.
2도면과 실제 위치가 따로 논다배치도의 px 거리와 현장의 m 거리가 맞지 않으면 "8 m 이내 접근 금지" 같은 기준을 적용할 수 없습니다.
3경보가 한 방향뿐이다작업자는 장비가 오는지 모르고, 운전원은 사각지대에 누가 있는지 모릅니다. 관리자는 사고 뒤에야 압니다.

✕ 기존 방식

  • 종이 배치도에 위험 구역을 손으로 표시
  • 신호수·안전 펜스에 의존, 장비 이동 시 갱신 안 됨
  • 근접 경보 장치는 장비 한 대 단위, 현장 전체 현황 없음

✓ SOC-MAP

  • 현장을 위경도에 등록하고 모든 거리를 실제 m로 계산
  • 운전원 휴대폰 = 장비 위치 → 위험 반경이 실시간으로 이동
  • 작업자 ↔ 운전원 ↔ 관리자 3방향 경보와 기록
  • 위험 구역을 피하는 안전 경로를 자동 탐색
핵심 기능

배치도 한 장에서 현장 관제까지

관리자 PC의 웹 화면과 현장 인원의 휴대폰 웹 앱, 둘이 하나의 서버 프로젝트로 연결됩니다. 설치할 앱은 없습니다.

⚠️

KOSHA 기준 위험도 엔진

장비별 작업반경, 후방 사각지대, 붐·지브 회전 반경, 아웃트리거를 Red / Orange 구역으로 모델링하고 0~100 위험도로 합산합니다. 풍속·연약지반·고압선 이격거리 같은 현장 조건이 넘으면 장비 영향 반경 전체가 전면 통제됩니다.

안전보건규칙 제37조 · 제322조KOSHA D-C-4-2025겹치면 최댓값
📍

실제 GPS 좌표의 공사 프로젝트

주소 검색이나 좌표로 현장 원점을 정하면 WGS84 국소 접평면(ENU) 좌표계가 생깁니다. 위성 지도와 도면, 장비가 같은 미터 좌표 위에 놓입니다.

ECEF 변환Vincenty 검증
📡

휴대폰 위치 상호 공유

QR이나 6자리 참여 코드로 합류합니다. 운전원 휴대폰의 위치·방향이 곧 장비의 위치·방향이 되어, 장비가 움직이면 위험 반경도 함께 움직입니다.

WebSocket 1 Hz작업자 · 운전원
🚨

3방향 단계별 경보

작업자에게는 접근 시 진동·방위 안내, 진입 시 사이렌. 운전원에게는 반경 안 작업자 수. 관리자에게는 진입·SOS·신호 끊김을 소리와 기록으로 알립니다.

SOS 길게 누르기웹훅 연동
🧭

위험 회피 안전 경로

건물·울타리를 장애물로, 위험도를 비용으로 둔 A* 탐색. 최단 경로와 나란히 그려 거리 증가율과 위험 노출 감소율을 보여줍니다.

비용 = 거리 × (1 + w·R)
🏢

AI 도면 건물 인식

YOLOv8 세그멘테이션으로 배치도에서 건물 외곽을 찾습니다. 타일 분할·반전 추론으로 큰 도면의 작은 건물도 잡고, 수정한 결과는 학습 데이터로 저장됩니다.

YOLOv8n-seg평가 · 재학습 스크립트

모두

⚖️ 위험도 공식 장비 1대 · 0~100

우선순위가 높은 구역부터 판정하고, 여러 위험원이 겹치면 최댓값을 씁니다.

# 0. 전면 통제 — 풍속 초과 · 침수 · 고압선 이격 미확보 R = 100 (장비 영향 반경 전체) # 1. Red Zone — 작업반경 · 붐/지브 아래 R = 100 # 2. Orange Zone — 후방 사각지대 · 아웃트리거 R = clamp((E_orange + S_penalty) × W_freq − H_mitigation) # 3. 영향 반경 안 기타 R = clamp(S_penalty × W_freq − H_mitigation)

🎯 위치 정확도 처리

  • 칼만 필터 — 등속 모델로 GPS 흔들림을 줄이고 보행 속도(1.4 m/s)를 따라갑니다.
  • 이상치 제거 — 예측에서 약 4σ 벗어난 측위는 버리되, 같은 자리에 반복되면 실제 이동으로 봅니다.
  • 오차 반영 경고 — 측위 오차만큼 경고 거리를 넓히고, ±60 m보다 나쁜 측위는 판단에서 뺍니다.
  • 측량 — 60초 가중 평균으로 도면 정합용 기준점을 잽니다.

세 가지 실행 방법

Windows 기준입니다. Python 3.10 이상이 필요하며, 실행 스크립트가 첫 실행 때 가상환경과 패키지를 설치합니다.

① 서버 없이 둘러보기

관리자 화면만 브라우저로 엽니다. 배치·경로·3D·측정을 쓸 수 있고, 휴대폰 연동과 AI 인식은 꺼집니다.

# 이 홈페이지의 라이브 데모

AI 건물 인식과 서버 프로젝트를 씁니다. 실행하면 관리자 화면이 열립니다.

같은 와이파이의 휴대폰이 HTTPS로 접속합니다. 방화벽 창에서 개인 네트워크 허용을 누르세요.

한계와 다음 단계

정직하게 적어 둔 한계

스마트폰 웹 앱으로 할 수 있는 만큼 했고, 실제 운영에 필요한 부분은 다음 단계로 남겼습니다.

현재

스마트폰 GPS 3~10 m 오차

칼만 필터와 오차 반영 경고로 보완합니다. 휴대폰 GPS는 HTTPS에서만 동작하고, 화면이 꺼지면 위치 추적이 멈출 수 있어 "신호 끊김"으로 알립니다.

다음

RTK GNSS · 네이티브 앱

블루투스 RTK 수신기로 cm급 위치를 받고, Android 포그라운드 서비스로 백그라운드 추적을 지원합니다. 좌표계와 필터 구조는 그대로 씁니다.

이후

실제 현장 데이터로 검증

다른 현장 도면으로 AI 인식을 평가·재학습하고, 설계값으로 둔 가중치(W_freq, 사각지대 각도)를 현장 자료로 보정합니다.
